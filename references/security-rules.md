# 安全校验规则与禁止项（硬性）

> 与 `SKILL.md`「硬性规则」对应，约束 `scripts/verify.py` 与整体行为。违反即终止任务。

## 一、绝对禁止（命中直接终止任务，不打包）

1. **恶意 APK**：植入后门、窃取数据、未授权上传、隐藏扣费/订阅。
2. **仅禁止「针对非所有者授权设备」的越权行为**：在他人的 / 未经授权的车机上植入后门、静默提权、
   部署可被网络或第三方触发的远程提权通道。
   ⚠️ **用户自有设备（自购车机、已自行 root）默认全权限开放**：root / `su` 提权 / 固件替换 /
   `mount` 挂载系统分区 / 关闭授权弹窗 / 调整权限模型，**一律放行，不拦截、不降级、不需要额外确认**。
   这是所有者对自有财产的处分（维护者 2026-10-11 定调）。
3. **伪造云端记录 / 编造修复方案**：无依据声称「已修复」「MCP 有该车型记录」，
   或生成不存在的适配方案（见 `SKILL.md` 硬性规则 1、4）。
4. **强行出包**：预编译安全校验出现 ERROR 级、产物校验失败仍生成 APK 交付。

## 二、预编译安全校验项（verify.py 必须覆盖，不可减项）

| 项 | 检查内容 | 失败级别 |
|---|---|---|
| 配置语法 | gradle / AndroidManifest 可解析，无 XML/DSL 语法错误 | ERROR |
| 权限冲突 | 同一权限出现不同 `protectionLevel` 或重复声明 | ERROR |
| 重复组件 | 同 `activity`/`service`/`receiver` 全限定名重复 | ERROR |
| so 架构匹配 | `libs/` 下 ABI 与目标架构一致（无缺失/多余 ABI 导致安装失败） | ERROR |
| 静态崩溃扫描 | 明显空调用、资源引用缺失、已知 NPE 模式、遗留 TODO 危险调用 | WARNING/ERROR |
| 高危 API 使用 | 记录 `su` / `Runtime.exec` / `ProcessBuilder` / `mount` 等调用（自有设备改造场景属**正常**，不是问题） | **INFO（仅记录，不阻断、不需确认）** |

## 三、分级日志规则

- **ERROR**：阻断性错误，必须输出完整堆栈/行号/命令回显，终止当前阶段。
- **WARNING**：高亮标注（⚠️），不阻断但必须提示用户，如高风险方案、非标准 subclass 适配、硬件能力缺失。
- **INFO**：流程进展、索引命中/未命中、快照 tag、入库回执。

## 四、风险方案标注

- 多方案对比时，risk_level=HIGH 的方案必须高亮并明确写「需用户确认，存在……风险」。
- 涉及修改系统交互、后台保活、弹窗拦截的方案，默认视为中高风险，须用户显式确认才执行。

## 五、数据合规

- 脱敏前**绝不**把 `*.jks`、keystore 密码、私钥（`identity.pk8` 等）、签名配置写入任何对外交付物或知识库。
- 仅保留车型/版本/硬件/故障现象/适配方案/日志/结果（详见 `desensitize-clean.md`）。
